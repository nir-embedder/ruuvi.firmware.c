# nRF5 SDK 15 → nRF54 Zephyr migration audit

This is a **work-in-progress parity report**, not a sign-off. The actual local nRF54 board model, wiring, and fitted sensors have not been identified. A separate NCS v3.4.1 workspace was fetched at `/tmp/ruuvi-ncs-v3.4.1` for candidate builds; the earlier upstream Zephyr 4.4.0 workspace remains at `/tmp/ruuvi-zephyr-workspace`. Neither proves the user's hardware identity or running firmware. The editor's STM32H743 hardware context does not describe this project. Do not transplant nRF52 GPIO numbers or flash page addresses to nRF54. An empty/invalid DF5 sensor field is not evidence of a working sensor.

**Do not flash the history-enabled TAG candidate onto an existing board.** Its overlay relocates the secondary image and settings partition to reserve 60 KiB for history. The opt-in TAG sysbuild now compiles MCUboot and the application against the same modified devicetree layout, but the upgrade strategy, production signing keys, on-target boot/swap behavior and migration of existing storage must still be coordinated. A matching compile/link is not evidence that this partition map is safe on an already-programmed unit.

## Source baseline

The original application lives in `../nrf52_oldsdk/src`. Its default configuration is `application_config/application_mode_default.h` and `application_config/app_config.h`; board capabilities vary with `ruuvi.boards.c/ruuvi_board_*.h`. `main.c` wires together the lifecycle. `app_sensor.c`, `app_comms.c`, `app_heartbeat.c`, `app_dataformats.c`, `app_log.c`, `app_button.c`, and `app_led.c` define the observable behavior. Legacy tests are in `../nrf52_oldsdk/test`, the endpoint vectors in `../nrf52_oldsdk/src/ruuvi.endpoints.c/test`, and hardware integration tests in `../nrf52_oldsdk/src/run_integration_tests.c`. The old `app_sensor_handle()` only implements log reads, not configuration writes; the old password command checks the nRF52 FICR device ID and enables configuration on the **next** connection. Do not infer a writable settings protocol from this incomplete legacy implementation. On nRF54, the candidate unlock uses Zephyr Nordic `hwinfo_get_device_id()` (the driver reverses the two FICR ID words), then swaps the words to match the old eight-byte wire order; its value and persistence still need checking on the real board. A public hardware ID is **not a secret** and cannot be a release-grade authentication credential. Legacy scan-response UUID is the 128-bit NUS service, while 0xFC98 is conditionally carried in primary advertising data, not exposed as a separate GATT service. The legacy NFC driver uses a writable **Type 4 Tag** NDEF interface; Type 2 Tag examples are not a compatible substitute.

## Legacy build-mode matrix

Source is `../nrf52_oldsdk/src/application_config/application_mode_*.h`. ## Verification performed

- Host CMake/CTest passes **8/8** checks against the shared legacy endpoint sources (DF5, format rotation, legacy-primary AD byte budgets (DF5/DF7 exactly 31 bytes, C5 29, DF8+UUID 35 and invalid), 32-bit movement-counter modulo vectors for DF5/7/8/C5, fixed-width history, rotation/read/reboot state with fake flash, log-read/EOF 11-byte vectors including all eight acceleration/gyro empty-history destinations, NUS stream authorization/backpressure and the legacy password reply vector, NDEF Type 4 long/short record vectors with malformed/duplicate/unaligned buffer checks, and a public NIST AES-128 ECB block), also **8/8 under UndefinedBehaviorSanitizer**. Both suites were rerun after the invalid-sensor history change and now check that NaN-only records retain their interval and timestamps across a fake-flash restart. They exercise the portable protocol and fake history, not the Zephyr GATT/NFCT callbacks, sensor driver, or the application's main-loop scheduling. Run `cmake -S nrf54_zephyr/tests -B /tmp/ruuvi-formats-host -DCMAKE_BUILD_TYPE=Release && cmake --build /tmp/ruuvi-formats-host && ctest --test-dir /tmp/ruuvi-formats-host --output-on-failure` from the repository root. The AES host test requires an available mbedcrypto/PSA library (found here under Homebrew `mbedtls@3`); without it CMake omits that test, so check CTest's test count. Format-8/FA fixture encryption checks callback wiring but is **not** actual AES; the separate NIST vector validates the actual AES callback only. Neither supplies production keys.

### NCS writable NFC Type 4 Tag candidate (DK only)

The opt-in `nfc.conf` enables `CONFIG_NFC_T4T_NRFXLIB`, a dedicated non-ISR NFC callback thread and `CONFIG_POLL`. `src/nfc_codec.c` now implements the narrow legacy Text-record wire format with byte-wise BE length writes and strict MB/ME/CF/IL/TNF/status/length validation; it does not use NCS v3.4.1's NDEF encoder, whose long-record `uint32_t *` length store can be unaligned. Nordic's T4T emulation library still owns the NFCT hardware. NCS v3.4.1 `samples/nfc/writable_ndef_msg` itself links for `nrf54l15dk/nrf54l15/cpuapp`; its success is SDK/board support evidence, not Ruuvi behavior. The Ruuvi application also links with both `dfu.conf` and `nfc.conf` using `west build --sysbuild -d /tmp/ruuvi-ncs-dk-dfu-nfc -b nrf54l15dk/nrf54l15/cpuapp --extra-conf <app>/dfu.conf --extra-conf <app>/nfc.conf <app>` from the separate NCS workspace. An unrelated test RSA key rejected an earlier image, not this digest; no physical signature rejection has been tested. `src/nfc.c` is compiled only for the NCS Type 4 library and asserts an enabled NFCT with no `nfct-pins-as-gpios` UICR choice. The NDEF file uses two alternating 512-byte aligned RAM buffers and a correct two-byte big-endian NLEN. The metadata strings identify this **demo** image, not a verified production firmware/hardware revision. A reader's 11-byte `dt` command is processed only after field-off; a response is readable on a subsequent tap, and multi-frame log responses need repeated NFC reads/field transitions. Invalid NLEN, malformed Text status/language, oversized/short commands and unhandled operations cannot silently become configuration writes. Unsupported writes still return 0xEA; on DK without a history partition log read is rejected. BLE-NUS and NFC share the main-thread history logic but no physical concurrency test exists.

Both upstream Zephyr 4.4.0 and NCS v3.4.1 `qemu_cortex_m3` Twister (run `west twister -T <app>/tests/nfc_codec -p qemu_cortex_m3 -O /tmp/ruuvi-twister-nfc-upstream-v3 -i` from the upstream workspace; use output `/tmp/ruuvi-twister-nfc-ncs-v3` from the NCS workspace) ran **3/3 portable codec tests**: legacy-order long-format UTF-8 records, a single-record byte-vector with embedded zeroes, and malformed NLEN/language/length rejection. Host CTest's eighth suite additionally checks a complete 122-byte NLEN legacy-order `ID`/`MAC`/`SW`/`Data:\0` startup vector, unaligned buffers under UBSan, short-record reader input, duplicate commands and rejected CF/IL/reserved TNF flags. The fixture is derived from legacy source format, not a captured tag dump. This does *not* exercise nrfxlib NFCT interrupts, field arbitration, writable-file pointer swaps, NFC read/reply pacing or any antenna. `NFC_T4T_EVENT_NDEF_UPDATED` may follow partial NLEN writes, so parsing happens after field-off from a bounded snapshot. A real reader and antenna are required before claiming transport parity. A dedicated higher-priority NFC callback thread plus a read of NFCT's live `FIELDPRESENT` status reduce the deferred-callback race before a buffer swap, but do not prove there are no new-field arrivals between the check and emulation stop; a live reader/logic trace must exercise this boundary. Two queued 512-byte write snapshots retain the newest write on overflow and count displaced older requests, which then receive no response; this is not a flow-control protocol. Continuous-field watchdog behavior, queue overflow, interrupted writes and restart persistence are still release gates. Devicetree assertions check desired UICR only: read back the actual persistent `nfct-pins-as-gpios` state on the selected physical board before any NFC flash. The candidate is **not** enabled in upstream-Zephyr or default NCS builds. ## Next implementation step
